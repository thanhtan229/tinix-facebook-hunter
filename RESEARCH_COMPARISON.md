# RESEARCH_COMPARISON.md

> **Comparative Repository / Technology Research**
>
> This document compares multiple repositories, frameworks, technologies, or implementation approaches using a common evaluation framework.
>
> Its purpose is to identify proven strengths, tradeoffs, transferable patterns, and the smallest coherent combination that best fits the target project.
>
> It is not a popularity ranking and not a “best-of-everything” architecture exercise.

## 20. Research Phase Boundary

Unless explicitly requested, comparative research does **not** authorize:

- implementation;
- refactoring;
- dependency installation;
- migration;
- release/package work;
- automatic modification of `PLAN.md`;
- automatic modification of `ARCHITECTURE.md`.

The research output should inform the next decision-making step.

## 21. File Naming and Maintenance

For comparative research performed after a project has started, use:

`research/RESEARCH_COMPARISON_<topic>.md`

Examples:

```text
research/RESEARCH_COMPARISON_messaging_platforms.md
research/RESEARCH_COMPARISON_agent_frameworks.md
research/RESEARCH_COMPARISON_storage_engines.md
```

Use short, descriptive `lower_snake_case` topic names.

If research is repeated for the same topic:

- update the existing file when appropriate;
- update dates and researched versions;
- do not create unnecessary `v2`, `v3`, `final`, or `latest` copies.

Create a new file when the research objective is materially different.
